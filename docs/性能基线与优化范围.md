# 上线前性能基线与优化范围

阶段 1 记录于 2026-09-21，业务代码尚未修改。当前未提交工作已原样备份到 `/private/tmp/ledger-performance-20260921-baseline/source`，同目录保存原始 git status/diff/stat、SHA-256、230/230 测试与原生编译日志和 before.json。

## 方法与边界

- 固定合成数据：200 客户、1000 发货（每笔 2 行）、1000 收款、400 账期、1000 审计，快照约 2.79 MB。用于压力分析，不代表正式数据量；没有访问正式数据库。
- 本机 Node 执行真实页面 JS、真实仓储、真实领域规则，模拟微信 API，统计初始化 setData、JSON UTF-8 字节数和 storage.read 深拷贝次数。计时包含诊断开销，不能解释为微信视图层或 iPhone timing。
- 云端执行真实入口，SDK 替换为只读假数据库；每条查询注入 3 ms 延迟，只用于比较串行依赖，不能解释为真实云 DB 延迟。模块加载以 5 个独立 Node 进程测量，SDK 本身不计入这一组。
- 本机微信原生编译器可用；开发者工具自动状态读取延迟约 255 秒，未取得可重复的模拟器性能记录。冷/热启动、首屏可操作、实际跳转/返回/Tab 帧率与真机内存须用 iPhone 16 Pro 验收。

## 按测得影响排序

1. **首页/客户列表全企业深拷贝被客户循环放大。** `loadPage → getDashboard/listClients → getClientLedger → getClient/listBillingPeriods/listShipments/listPayments → storage.read`。200 客户下分别读取并复制企业根对象 804/801 次，累计约 2.25/2.24 GB，带诊断的 model 构建约 7.99/8.06 秒。优先在一次同步、只读页面计算内共用一个脱离原始缓存的工作副本，结束立即释放；不改变领域公式和服务端写入仓储。
2. **快速记账重复传输产品选项。** 初始化一次 setData 430,732 B；产品全量和标准/自定义子集均传给视图，但 WXML 只展示筛选后的选项。客户/历史也先传全量再传筛选结果，分别 175,294/133,955 B。
3. **Excel 顶层依赖污染普通云调用。** `index → statement-export-file → statement-excel → exceljs`；5 次冷进程均捕获一次 ExcelJS 加载。SDK stub 下入口 require 中位数约 58.67 ms。普通 bootstrap/saveClient/postShipment/recordPayment/closeBillingPeriod/读取都经过这一模块入口。
4. **快照读取串行。** 已有真实 OPENID/membership 校验在前；随后企业文档和 8 个集合顺序读取。常规 bootstrap 共 10 次 DB 查询，最大并发 1；3 ms 假 DB 延迟下约 35.91 ms。仅将身份/企业读取后的独立集合读取并行，事务内读取顺序保持原样。
5. **长列表节点随全量增长。** 客户/历史/发货/收款没有渲染分段；产品已限 150，审计已限 200，选择器已限 80。先减少无用数据传输，再仅对可证明收益的列表评估渐进渲染，保留完整搜索、排序和计数。

## bootstrap 与刷新事实

`App.onLaunch` 只初始化云 SDK，没有 bootstrap。正式页走 `loadPage → privacy gate → prepareRepository → bootstrap`；快速记账走自己的 privacy gate 后调用 prepareRepository。`prepareRepository` **原本已有 in-flight Promise 去重**，并在成功/失败后清理。加入企业页直接调用 bootstrap；未发现普通页面 onLoad/onShow 同时重复 bootstrap。每次已完成后的页面进入/返回仍重新请求，保障最新 membership 与多人账本；本轮不增加跨请求 TTL 或缓存角色授权。

页面通常没有在刷新前清空 data，主要是每次都显示全局“加载中”。可仅在同一页面同一仓储已有成功内容时改用导航栏刷新提示，保持服务端检查次数；首次页面仍等待服务端。通用 loadPage 也被写操作使用，因此不将其 callback 变成 stale-while-revalidate 的双次调用。

## 暂不做

- 领域规则、账期/价格/权限、导出内容、事务、安全检查和数据库结构保持原样。
- 不删审计/成员/历史字段以缩短 bootstrap；无法证明每个字段都非业务所需。
- 主包源码清单 385,427 B（不是微信最终压缩包），24 页，无图片/第三方前端大依赖；ExcelJS 属于云函数 node_modules。低频页共享仓储和产品数据，分包收益有限且已有 Tab 依赖过滤历史风险，待最终清单复核后决定，当前不分包。
- 不改已有产品 150 条、审计 200 条、选项 80 条的显示规则；不为性能扩充功能或改文案。
