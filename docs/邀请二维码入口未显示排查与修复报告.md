# 邀请二维码入口未显示排查与修复报告

日期：2026-09-22。范围：只排查按钮渲染、前端目录与打包，以及页面回归。

## 结论

**本地 WXML 和管理员判断没有缺失。问题发生在开发者工具使用的旧编译产物及前端依赖打包上。**

已经修复本地编译/打包状态：当前开发者工具的真实管理员账号、active invite 页面，已实际显示“分享给微信好友”“作废邀请”“邀请二维码”。本次没有点击二维码生成，没有修改云函数，没有部署或上传。

## 根因证据

1. 用户截图显示旧文案“分享邀请卡片”，没有二维码入口。任务开始时，在开发者工具模拟器中复现完全相同的按钮状态；当前成员身份为管理员，邀请显示有效。
2. 开发者工具窗口的 projectpath 指向 `/Users/zhengxiaotuo/Desktop/codex项目/记账工具`，与本轮修改目录一致。项目 `miniprogramRoot` 为 `./`，实际路由在 `app.json` 注册；检查项目区也只有这一份 `pages/members/members.wxml`。不是写进了报价项目或另一份成员页。
3. 磁盘上的成员页已经包含“邀请二维码”，分享文案已经是“分享给微信好友”。在任何修复前，直接用本机微信原生 WCC 编译此 WXML，再执行其渲染函数，admin + active invite 得到三个按钮，二维码按钮没有 disabled。由此排除了 WXML 条件本身吞掉按钮。
4. 在开发者工具中点击普通“编译”，模拟器仍显示旧文案、仍没有二维码。这说明普通编译没有把当前页面和新增依赖完整刷新到运行包。
5. 通过工具菜单只清除“编译缓存”并重新编译后，控制台明确出现：

   ```text
   Error: module 'services/invite-qrcode.js' is not defined,
   require args is '../../services/invite-qrcode'
   ```

   此时已读到成员页新 JS，但新增前端 helper 未进入运行包。只清除项目文件列表缓存并重编译后，仍曾出现相同缺模块错误。
6. 项目保持开启 `ignoreDevUnusedFiles`、`ignoreUploadUnusedFiles`，此前显式包含项只有 `pages` 文件夹。加入二维码前端 helper 的精确包含项后再次编译，缺模块错误消失；重新进入“我的 → 企业成员”，已实际观察到二维码入口和新版分享文案。

可确定的是：**原上传源目录正确，但本机运行产物未包含完整最新页面/依赖。** 真机截图与修复前本机旧产物一致。本轮未下载已上传的体验版二进制，也未核对微信后台绑定的上传记录，因此不把“后台具体绑定哪次上传”写成已独立验证的事实。

## 页面测试增强

上一轮测试主要运行页面 JS，并检查 WXML 文本里存在对应绑定；这不能证明微信条件编译后的节点真的存在。本轮新增 `tests/helpers/wxml-render.js`，使用与 `npm run check` 相同的微信原生 WCC，把真实 WXML 编译成渲染函数并检查实际节点树。

强化原来的两个身份用例：

- 先通过真实 ledger 入口的本地事务模拟创建 active invite，再以测试 WXContext 中的 admin 身份加载页面；确认有且只有一个“邀请二维码”按钮，按钮可用，且此时尚未生成图片。
- 同一企业已存在 active invite，改用普通 member 的服务端身份加载页面；确认不渲染二维码入口。

新增五项回归：

1. 初始未知身份不显示邀请入口，所有二维码相关 data 正确初始化。
2. 普通 member 即使残留 active invite 或旧图片，也不显示入口及二维码图片。
3. 管理员无当前 invite，仍显示可用的二维码入口。
4. 邀请加载、二维码生成、图片保存状态只禁用按钮，不隐藏入口。
5. 当前小程序根目录、原 pages 包含项及新 helper 精确包含项正确，两项无依赖文件过滤继续开启。

测试依赖本机已安装的微信原生 WCC，也支持通过 `WECHAT_WCC_PATH` 指定位置；没有安装新依赖，没有用正则模拟 `wx:if` 渲染结果。
