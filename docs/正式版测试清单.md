# 正式版微信开发者工具测试清单

## A. 环境与登录

- [ ] 开发者工具使用独立 AppID `wx5093ae94c1ece97b`。
- [ ] 已选择正式云环境，十个集合（含 `member_invites`）已创建。
- [ ] `ledger` 云函数已“云端安装依赖”并部署。
- [ ] 原管理员进入后仍连接原企业；任何无 membership 微信只显示未授权页，绝不自动建立企业或管理员。
- [ ] 企业名称可保存，重新编译后仍保留。
- [ ] 数据库集合已禁止客户端直接读写。

## B. 双微信成员协作

- [ ] 管理员在“我的 → 企业成员”生成邀请，页面显示有效期和“有效”状态，并可分享到同事群。
- [ ] 同一个邀请分别供第二、第三个微信号加入；两者角色均为普通成员，且 `tenantId` 与管理员相同。
- [ ] 同一微信重复点击邀请提示“你已加入该企业”，不产生第二条 membership。
- [ ] 已停用成员不能借邀请重新加入；只能由管理员恢复原 membership。
- [ ] 管理员作废邀请后，聊天中的旧卡片不能继续加入；重新生成的新邀请可以正常使用，旧邀请不能恢复。
- [ ] 超过 `expiresAt` 的邀请和伪造令牌不能加入。
- [ ] 任何陌生微信都不会自动创建企业，且前端伪造 `tenantId/memberId/role` 无效。
- [ ] A、B 都能看到双方创建的客户和全部账目。
- [ ] “我负责的”只按客户或历史账期负责人筛选，不按录入人筛选。
- [ ] B 给 A 负责客户记发货/收款后，负责人仍为 A，录入人/登记人为 B。
- [ ] 管理员可只转移客户负责人，也可连同当前账期一起转移；已结清历史不变。
- [ ] 停用仍负责客户的成员时必须先选择接替人；停用后该微信号不能继续加载或写入企业数据。
- [ ] 成员改名或停用后，历史负责人和操作人姓名快照保持原值。
- [ ] 最后一个管理员和当前登录管理员不能被停用。

## C. 客户、产品与价格

- [ ] 新增客户，填写名称、联系人、电话、结账日和备注。
- [ ] 用名称、联系人和电话均能搜索客户。
- [ ] 修改客户后重新进入仍正确。
- [ ] 标准规格可搜索、只读、不显示通用价格。
- [ ] 新增、编辑、停用一个自定义产品；停用不影响旧发货详情。
- [ ] 在客户账本进入“该客户价格表”，新增并修改一个元/米、元/根或元/箱价格。
- [ ] 另一个客户不会继承该价格。
- [ ] 普通成员创建一个无发货、收款、账期和客户价格的测试客户，可以二次确认后删除。
- [ ] 普通成员给测试客户记一笔发货后再删除，系统明确拒绝并要求联系管理员。
- [ ] 管理员删除空客户只走普通确认；如果确认期间新增了业务，服务端拒绝快捷删除并要求重新预览。
- [ ] 管理员删除有账客户时显示发货、收款、账期、客户价格、进行中账期和未收金额，并要求输入完整客户名称。
- [ ] 管理员强确认后，客户及客户专属账务消失；共享标准/自定义产品、其它客户、成员、企业、邀请和审计仍存在。
- [ ] “我的 → 操作记录”能看到删除客户的执行人、时间、客户名称和删除数量摘要。
- [ ] 使用已删除的客户、账期或发货旧链接时提示资源不存在，不出现空白页或 JavaScript 错误。

## D. 核心快速记账回归

- [ ] `4040开口白色100` 匹配白色 40×40 粗齿、100米。
- [ ] `2525开口白色100` 自动纠正为细齿并显示说明。
- [ ] `白色4040，1.2米长的1000根` 保留特殊长度和1000根，不降级为普通标准品。
- [ ] 创建 `白色装潢1525，1.3米长` 后，相同长度别名能复用已有自定义产品。
- [ ] 未写颜色时要求人工选色，不默认灰色。
- [ ] 缺价时整单锁定；补价后才能确认入账。
- [ ] 数量单位与计价单位不一致时，未确认换算不能入账。
- [ ] 关闭“保存客户价”时只影响本次；开启后下一单自动读取。
- [ ] 二次确认后发货进入正确客户账本，首页总应收同步增加。
- [ ] 物流信息保持原样；运费留空时显示 `¥0.00`，且总额等于商品合计。
- [ ] 输入运费 `120`后，确认区显示商品合计、运费 `¥120.00`和含运费本次合计。
- [ ] 输入运费 `12.50`后正确保存；负数、三位小数或非数字不能入账。

## E. 账本、修正与审计

- [ ] 客户账本正确显示本期货款、已收、剩余、发货次数。
- [ ] 每笔发货详情显示商品、原数量、单位、成交单价、人工换算和金额。
- [ ] 发货详情显示商品合计、运费和本次合计；客户账本应收包含运费。
- [ ] 修正未结清账目必须填写原因。
- [ ] 修正后金额更新，详情中保留“创建”和“修正”记录。
- [ ] 将已入账运费从 `120` 改为 `80`，本次合计、本期应收和剩余应收同步减少 `¥40.00`，审计记录保留前后快照。
- [ ] 已有收款时，不能把修正后货款改到低于已收金额。
- [ ] 已结清账单不能直接修改。

## F. 收款、结清与历史

- [ ] 记录一笔部分收款，剩余应收正确减少。
- [ ] 再记录第二笔收款，支持不同日期、方式和备注。
- [ ] 收款金额超过剩余应收时被拒绝。
- [ ] 最后一笔收款使剩余为0后，显示“暂不结清 / 确认结清本期”，账期仍保持进行中。
- [ ] 普通成员是当前账期负责人时，收齐款后可以确认结清；结清审计记录该成员为实际操作人。
- [ ] 普通成员只是客户负责人、但不是当前账期负责人时不能结清；页面不显示结清入口，直接请求也被服务端拒绝。
- [ ] 非负责人普通成员即使把余额收至0也不能结清，管理员仍可代为结清任意账期并记录实际管理员操作人。
- [ ] 只收取商品金额、未收运费时不得结清；商品与运费全部收齐后仍需用户确认结清。
- [ ] 选择“暂不结清”后继续发货，仍写入原账期。
- [ ] 用户确认结清后账期出现在“历史”，完整发货、成交价、收款和对账单仍可查看。
- [ ] 9月开始、10月结清的账期只生成一张跨月历史账单。
- [ ] 结清后再发货会自动开启新一期，不修改旧历史账单。

## G. 对账单与首页

- [ ] 对账单默认显示整个当前账期（可跨月），包含客户、期号、起止日期、每次发货、收款和金额汇总。
- [ ] 对账单每次发货都显示商品小计、运费和本次合计；账期总货款包含全部运费。
- [ ] 账期结清后从“历史”重新进入，原商品金额、运费和总金额仍保持不变。
- [ ] 首页总应收、未结客户、最近记账、最近收款均与账本一致。
- [ ] 首页“+ 记一笔”可直接进入正式记账流程。
- [ ] 规则识别测试页只在开发版且当前账号为 admin 时出现；体验版和正式版不显示，直接路由也不可使用。

## H. 异常与真机

- [ ] 入账提交时断网，恢复后重试不会重复生成记录。
- [ ] 快速连续点击确认不会重复入账或收款。
- [ ] iPhone 与 Android 真机检查输入法遮挡、滚动、底部按钮和弹层。
- [ ] 20—30 条常用真实订单文本回归通过。
- [ ] 用两个已加入同一企业的微信号验证实时刷新；再用隔离测试数据验证不同 `tenantId` 无法交叉读取。
- [ ] 数据备份和恢复演练完成。
