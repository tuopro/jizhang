# 企业成员邀请小程序码功能报告

日期：2026-09-22。范围：当前 `jizhang` 本地最新源码上的增量实现。

已完成管理员入口、官方微信小程序码生成、二维码预览和保存、scene 解析、隐私同意后恢复邀请，以及服务端和页面回归。**未部署、未上传体验版、未提交微信审核、未修改正式数据库或云存储权限、未提交 Git。**

## 1. 原卡片邀请链路核对

| 环节 | 本轮开始时的真实实现 |
| --- | --- |
| 管理员入口 | `pages/members/members` 的邀请区域；页面 bootstrap 取得真实身份，admin 才读取当前邀请 |
| 当前邀请 | `getActiveMemberInvite` 按服务端 membership.tenantId 查询 `member_invites`，选择 active 且未过期的最新记录 |
| 生成 | `createMemberInvite` 在事务内根据真实 OPENID 重读 active admin；存在有效邀请则直接复用，没有才创建并写 `CREATE_MEMBER_INVITE` 审计 |
| 文档字段 | `id`、`tenantId`、`token`、`createdByMemberId`、`status`、`expiresAt`、`createdAt`、`updatedAt`；撤销时增加 `revokedAt`、`revokedByMemberId` |
| token | `crypto.randomBytes(24).toString('hex')`：24 随机字节、192 bit、48 字符，只含 `0–9a–f`。此结论来自当前生成代码与本地执行，未读取正式邀请数据 |
| 有效期 | 从生成时间起 7 × 24 小时；已有有效邀请再次生成不会续期 |
| 多人复用 | 加入不修改 invite；不写 `status=used`、`usedAt` 或 `usedByOpenid` 数组 |
| 作废 | `revokeMemberInvite` 在事务内重读管理员及目标邀请，核对真实 tenant，然后按原规则撤销并写 `REVOKE_MEMBER_INVITE` |
| 分享 | `onShareAppMessage` 使用服务端 `invite.path`：`/pages/join-enterprise/join-enterprise?inviteToken=<编码后的token>` |
| 实际加入页 | `pages/join-enterprise/join-enterprise`，已在 `app.json` 主包注册 |
| 启动参数 | 原 `App.onLaunch` 只初始化云能力；邀请参数由目标页 `onLoad(options)` 处理，不依赖 app 全局 tenant 或本机业务缓存 |
| 隐私恢复 | `runAfterPrivacyConsent` 将原 route/query 保存在 `services/privacy-consent.js` 的模块变量 `pendingRoute`；同意后 `takePendingRouteUrl` 恢复页面。只持久化隐私版本和同意时间 |
| 原预览 | 加入页先 bootstrap；陌生用户才 inspectInvite。服务端 inspect 校验 token 对应 invite 并返回企业名称、有效期 |
| 原加入 | 用户填写姓名并点击按钮后调用 acceptInvite；真实 OPENID 从 `cloud.getWXContext().OPENID` 取得，事务内重新读取 invite 和既有 membership，并审核显示姓名 |
| 成员生成 | 服务端从 OPENID 推导 memberId；tenantId 来自真实 invite；`role='member'`、`status='active'` 固定。前端姓名是待审核文本，不是身份凭证 |
| 加入审计 | 原 `JOIN_ENTERPRISE_BY_INVITE`，操作人为本次真实创建的 member；包含原 inviteId、memberId、姓名快照、加入时间 |
| 异常规则 | revoked 明确作废；expired 明确过期；旧 used 无效；同企业 active membership 提示已加入；disabled 不得重建；已绑定其它企业拒绝 |

前端的管理员按钮只控制展示，服务端不信任前端 role、tenantId、openid、memberId、ownerMemberId 或 admin 标记。陌生微信持有效邀请可以请求预览和确认加入，没有邀请仍不能通过 bootstrap 进入企业。

## 2. 本轮实现

### 2.1 同一邀请的第二种传播形式

企业成员页保留“分享给微信好友”，新增“邀请二维码”。没有当前有效邀请时，服务端调用原 `createMemberInvite`，继续沿用原 7 天有效期、复用规则和生成审计。已有邀请时使用原 invite.id；传入其它企业、已过期或已作废的 invite.id 会被拒绝，不替换为其它邀请。

二维码卡片展示企业名称、到期时间、“微信扫码加入企业”和“扫码后需确认加入企业”，提供预览、保存和收起。分享卡片与小程序码最终指向同一条 `member_invites`。重新生成图片不续期，不额外创建邀请或预览审计。

### 2.2 scene 采用新增 qrSceneCode

原 token 有 48 字符，不能直接放入最多 32 字符的微信 scene。本轮**不截断或更改 token**，只给实际生成二维码的原邀请文档懒加载 `qrSceneCode`：

- 独立的 `crypto.randomBytes(24)`，保留 192 位随机强度。
- 转为不带填充的 base64url，恰好 32 字符，字符集为 `A–Z a–z 0–9 _ -`。
- 不含 tenant、member、openid、role、名称、联系方式或账目信息，也不从这些信息派生。
- 在事务内检查候选是否已存在，碰撞最多重试 5 次；同一 invite 已有 code 时复用并校验唯一匹配。
- 解析时只接受精确格式且只有一条匹配的邀请；任何重复映射均拒绝，不能任意选一个 tenant。
- 官方图片调用结束后再次校验身份、邀请状态和 code 唯一映射；同一邀请的并发请求通过事务重试复用最终 code。

新增字段只有 `member_invites.qrSceneCode`。没有新集合、没有批量迁移、没有历史数据回填；原 token、状态、有效期和原时间字段保持不变。没有新增索引配置。随机生成加事务查重是应用层实现；正式云数据库的并发行为仍需部署后验证，本地事务模拟不等于线上验收。

### 2.3 微信官方调用与版本

调用 `cloud.openapi.wxacode.getUnlimited`：

| 参数 | 实际值 |
| --- | --- |
| page | `pages/join-enterprise/join-enterprise`，无起始 `/`、无 query string |
| scene | 上述 32 字符 opaque code |
| envVersion | 前端 `wx.getAccountInfoSync().miniProgram.envVersion`；服务端只允许 develop、trial、release |
| checkPath | release 为 true；trial/develop 为 false，使尚未出现在正式发布版中的真实加入页也可生成二维码 |
| width | 430 |

当前运行 develop 生成 develop 码，trial 生成 trial 码，release 生成 release 码。缺失/非法版本直接拒绝，不猜版本。版本值只传给官方二维码 API，不能改变 tenant、membership、role 或邀请验证。

已核对[微信官方 getUnlimitedQRCode 文档](https://developers.weixin.qq.com/miniprogram/dev/server/API/qrcode-link/qr-code/api_getunlimitedqrcode.html)中的 scene 长度/字符集、page、版本、checkPath、云调用 camelCase 示例、buffer 返回及 `decodeURIComponent(query.scene)` 用法。

`cloudfunctions/ledger/config.json` 的 `permissions.openapi` 现在同时保留：

```json
["security.msgSecCheck", "wxacode.getUnlimited"]
```

没有自行申请 access_token，没有新增 AppSecret、SecretId、SecretKey、第三方服务或依赖。

### 2.4 扫码、隐私与确认加入

扫码落到原加入页，参数来自 `options.scene`。页面在隐私 gate 之后只解码一次，并严格校验本项目规定的 code 格式。混合 scene 与 inviteToken、非法编码、错误长度等直接拒绝；格式正确但不存在的 code 由服务器拒绝，不回退到缓存企业。

隐私服务本身逐字节未改。scene 与卡片参数都随原 route/query 暂存在 JS 模块内存；未同意时不会调用业务云函数。未将 scene、token、二维码 base64 写入 wx storage、日志或 analytics。进程被终止后模块内存自然消失，用户重新扫码即可；没有为此增加持久化凭证。

二维码路径仍使用原两个 PUBLIC_ACTION：`inspectInvite` 和 `acceptInvite`。前端传 `{qrSceneCode}` 只帮助服务端找到真实 invite；卡片继续传 `{inviteToken}`，不会被换成另一套 membership 流程。

为避免“扫码被已有登录企业截走”，加入页现在先 inspect，再决定显示邀请或提示已加入。服务端 inspect 复用原 `validateInviteJoin` 判断 membership，增加 `status` 和 `alreadyMember` 结果；另企业 membership 直接拒绝。这也同时适用于卡片。原来页面先 bootstrap 后直接跳首页的展示顺序有所调整，分享路径、卡片 token 和业务授权规则不变。

陌生用户只会看到企业名称、有效状态、到期时间和姓名输入；按钮为“确认加入”。页面重新进入或前后台返回会再次 inspect，加载时清空旧企业信息；迟到响应不能覆盖已退出页面。最终 accept 不相信预览结果，事务内重读 invite 和 membership，姓名内容安全检查后再次检查到期时间；事务冲突重试也会重新校验。

### 2.5 权限、作废、停用和审计

新增的 `createMemberInviteQRCode` 是 active-member action，并在内部要求真实 admin；**没有新增 PUBLIC_ACTION**。生成前后事务均重读 OPENID 对应 membership 与其 tenant；前端伪造管理员、指定其它企业 invite、生成中被停用/删除/降为成员/变更企业均不能拿到图片。

accept 仍使用真实 WXContext.OPENID，成员构造函数完全未改。扫码者只能得到 member/active。没有审核人员特殊身份、固定审核 OPENID、自动加入、自动管理员或审核初始化入口。

作废与到期后，旧卡片和旧二维码都会在 inspect/accept 时读取同一邀请而失败。图片本身不会远程消失，但不能再用于加入。已经停用的 membership 会被原检查拒绝，不会重新创建。已加入同企业的 active 用户提示“你已加入该企业”并进入企业；不同企业拒绝。

原 `createMemberInvite`、`revokeMemberInvite` 和成员安全规则文件未改。`JOIN_ENTERPRISE_BY_INVITE` 审计对象结构、操作人和字段来源保持原样。生成二维码只在确需新建 invite 时产生原生成审计，不为每次图片预览新建审计。

### 2.6 图片返回和生命周期

采用 **buffer → base64 → 本机临时工作图片**，没有使用云存储中转：

1. 服务端只接受微信返回的 Buffer，校验 PNG/JPEG 文件头及 384 KiB 上限；异常响应、非图片、超大图片返回固定错误。
2. base64 最大 512 KiB，控制云函数返回体大小；超限不偷偷切换到公开文件或第三方服务。
3. 前端写入 `wx.env.USER_DATA_PATH/ledger-invite-qr-<时间>-<序号>.<png|jpg>`。文件名不含邀请凭证和企业身份。
4. 预览使用 `wx.previewImage`。生成/预览不申请相册权限，点击“保存二维码”才进入现有相册授权、拒绝提示、openSetting、saveImageToPhotosAlbum 流程。
5. 收起、重新生成、作废和页面退出会尽力删除本机工作文件；保存中退出会等保存结束再删。退出后迟到的图片写入也会清理。用户已保存到系统相册的图片保留。
6. 相册公共 helper 仅增加可选的授权提示文案，原账单调用不传新参数，默认文案和流程不变。未新增相册读取权限。

没有长期或短期二维码云文件，没有二维码 cleanup 云接口，没有修改云存储“仅创建者可读写”权限，没有调整 Excel cleanup 或 GC。本机删除属于尽力清理，不能保证系统强制终止进程时执行；这不会留下任何云端二维码文件。

官方 API 异常先转为固定错误，原响应、request、buffer、base64 不进入日志。二维码 action 的未知错误也统一为固定错误；本轮不记录 token、scene、openid、tenantId、企业名称或用户正文。企业名称仍由原保存流程审核，加入姓名仍经过原 msgSecCheck；opaque 凭证不发送给内容安全接口。

## 4. 后续部署与审核使用步骤（本轮未执行）

1. 重新部署 `cloudfunctions/ledger`，使新增 action、scene 解析和 `wxacode.getUnlimited` 权限生效。原 `security.msgSecCheck` 必须保留。不需要新依赖、集合或数据库迁移。
2. 重新上传小程序代码并设为体验版，使企业成员二维码入口与加入页 scene 解析生效。只部署云函数不能让旧客户端显示新入口。
3. 用已具备目标企业管理员 membership 的微信打开这次**体验版**，先确认当前企业是“德赛记账审核演示”，再进入“我的 → 企业成员 → 邀请二维码”。本功能不会替你创建审核企业或管理员。
4. 核对二维码卡片中的企业名、到期时间。点击“保存二维码”，在相册权限提示中按需授权，即可取得可上传审核辅助材料的真实小程序码图片。
5. 使用另一微信通过扫一扫或识别图片验证：未同意则先隐私同意，之后显示正确企业及有效期，输入显示姓名并确认加入，最终角色必须是普通成员；同时验证客户/账目仅来自该邀请所属企业。
6. 确认该版本的审核入口能实际打开二维码后，再将保存的图片作为该次提交审核的辅助材料。体验版中生成的二维码明确指定 trial，正式版生成的码指定 release；二维码不永久写死 trial。
7. 邀请只有 7 天。提交审核前检查到期时间；需要重新计算有效期时先“作废邀请”，再生成新邀请和二维码，并替换旧审核材料。只重新生成同一邀请的图片不会延长有效期。
8. 要让更新后的正式客户端上线，需要提交/重新提交微信审核。本轮没有进行任何部署、上传或审核提交。

**trial 访问的实际边界：**小程序码消除了“必须先成为管理员微信好友才能收到分享卡片”的传播要求，但不会授予微信平台的体验成员资格，也不能绕过微信对 trial/develop 的访问控制。审核人员能否由辅助材料打开对应版本，仍须以微信审核平台和指定账号的实际扫码结果为准；本地模拟测试不证明该平台权限已经具备。若真实扫码被微信版本权限拦截，应按平台规则处理体验/审核访问资格，不能恢复自动管理员或跳过本应用邀请确认。
