# 微信云开发部署与上线

## 1. 创建并选择云环境

1. 用 AppID `wx5093ae94c1ece97b` 在微信开发者工具打开项目。
2. 点击“云开发”，创建正式环境。
3. 确认开发者工具当前选择的环境就是将来生产使用的环境。

`app.js` 使用动态当前环境，不在代码中写死环境 ID，避免测试环境和生产环境混用。

## 2. 创建数据库集合

在云开发控制台逐个创建：

1. `enterprises`
2. `memberships`
3. `clients`
4. `products`
5. `customer_prices`
6. `shipments`
7. `payments`
8. `billing_periods`
9. `audit_logs`
10. `member_invites`

每个集合都设置为“所有用户不可读写”或等价的“仅云函数可访问”。规则内容参考 `docs/数据库权限规则.json`。

## 3. 部署云函数

1. 在开发者工具左侧找到 `cloudfunctions/ledger`。
2. 右键选择“上传并部署：云端安装依赖”。
3. 等待 `wx-server-sdk` 与锁定版本 `exceljs@4.4.0` 安装并部署成功。
4. 在云函数日志中确认没有集合不存在或权限错误。

不要只上传代码而跳过依赖安装。

客户删除功能不需要新增集合；但服务端删除、强确认和摘要审计逻辑位于 `ledger` 云函数，因此更新代码后仍必须重新执行一次“上传并部署：云端安装依赖”。

用户自由文本内容安全检查同样位于 `ledger` 云函数，并通过微信官方云调用 `cloud.openapi.security.msgSecCheck` 执行。`cloudfunctions/ledger/config.json` 必须在 `permissions.openapi` 中声明 `security.msgSecCheck`，否则云端可能返回 `-604101` 类权限错误。更新配置或代码后必须重新执行“上传并部署：云端安装依赖”；不需要新增数据库集合，也不需要配置第三方密钥或业务域名。

账单导出同样位于现有 `ledger` 云函数，不新增数据库集合或数据库权限。部署后应确认四个受保护 action 生效：`getStatementExportMeta`、`getStatementExportPage`、`createStatementExcel`、`cleanupStatementExportFile`。ExcelJS 是新增依赖，不能使用“仅上传代码”方式部署。

Excel 先上传到当前云环境的私有 `statement-exports/<tenant哈希>/<member哈希>/` 路径，客户端下载成功或失败后都会调用清理 action，并在失败时立即重试一次。正常生命周期为数秒；云函数在上传后、返回文件 ID 前异常终止时仍可能留下少量私有孤儿文件，部署后应在云存储控制台定期检查 `statement-exports/` 前缀。不得将该目录改为公开读。

## 4. 管理员身份与部署保护

1. 本项目正式云环境已有企业和管理员 membership；重新部署 `ledger` 云函数不会删除或重建这些数据。
2. 不要清空 `enterprises` 或 `memberships` 集合。正式版已取消“空数据库首人自动成为管理员”；空库不会从小程序公开初始化。
3. 若未来另建全新云环境，首个 enterprise 和 admin membership 必须由企业管理员在云开发控制台按已审核身份预置；不得临时恢复公开自动建企业逻辑。
4. 部署后先在原管理员微信上打开小程序，确认仍进入原企业，再用陌生微信确认只显示未授权页。
5. 验收时只新增测试客户，不要立即录入大批真实账目。

## 5. 邀请同事加入同一企业

1. 管理员进入“我的 → 企业成员 → 生成同事邀请”。
2. 页面显示邀请状态和有效期；点击“分享邀请卡片”可直接发送到公司同事群。邀请在 7 天内可供多个不同微信用户使用。
3. 同事从卡片进入，填写企业内部真实姓名或常用姓名，点击“加入企业”。
4. 服务端用邀请令牌和真实 `openid` 建立 `member` 关系；前端不能指定 `tenantId`、角色或成员编号。
5. 同一个微信重复点击不会创建第二条成员记录；已停用成员不能借邀请重新加入。
6. 如需提前终止邀请，管理员点击“作废邀请”；旧卡片立即永久失效。之后可重新生成独立的新邀请。

## 6. 安全验收

至少用两个不同微信账号执行同企业协作；跨企业隔离另用测试数据验证：

- A 为原管理员，能读取原企业并新增测试客户、价格、发货和收款。
- B 为陌生微信：不点邀请时只看到未授权页；点有效邀请后填写企业显示姓名并加入，才能看到同一企业账本。
- C 为第三个陌生微信：用同一有效邀请可加入；管理员作废该邀请后，C 在未加入前应只看到“邀请无效或已过期”。
- 管理员将 B 停用后，B 下一次刷新页面或发起操作应立即进入“账号已停用”页，且不能借邀请重新加入。
- 负责人筛选只影响列表，不得成为读取权限边界。
- 用隔离测试数据验证不同 `tenantId` 之间仍不可交叉读取。
- 修改前端请求参数或本机缓存中的 `tenantId`，云端仍必须使用成员关系中的企业。
- 连续点击两次“确认入账”或网络重试，同一 `requestId` 只能生成一条记录。
- 已结清历史账单不得修改。
- 用当前账期和已结清历史账期分别生成分页账单图片，核对每页企业/客户/期号/日期/表头/页码，长商品名不覆盖金额列，超长单笔发货正确显示“续”。
- 首次点击“保存全部图片”应出现相册授权；拒绝后仍可预览和分享当前页，重新进入设置授权后可逐张保存。
- 当前账期和历史账期分别导出 Excel，核对三个 Sheet、成交快照价格、运费、收款、负责人/操作人快照，并确认文件可打开和发送。
- admin 与普通 active member 均可导出；disabled、陌生微信和跨 tenant 参数必须被拒绝。
- 正常文本验收：新建测试客户，名称填写“杭州德赛电气”，备注填写“月底统一对账”，应正常保存。
- 风险文本验收：仅在测试客户备注中填写明显的违法违规推广测试语句，例如“赌博网站推广，加微信领取开户链接”，应提示修改内容且客户不能写入数据库。微信策略会调整，若该示例未命中，应使用微信官方 API 调试诊断工具核对当前策略，不得通过前端伪造审核结果。
- 在内容安全接口不可用的测试条件下，新建或修改自由文本应提示稍后重试；已有客户列表和历史账单仍应正常读取。

## 7. 备份与正式数据

1. 在云开发控制台设置数据库定时备份。
2. 导出一次测试备份，并在非生产环境做恢复演练。
3. 确认恢复后的客户、发货、收款、账期和审计记录数量一致。
4. 完成以上步骤后，再录入真实客户、电话和应收账款。

## 8. 提审前

- 补齐小程序名称、图标、类目和服务内容。
- 按 [隐私数据与微信接口盘点.md](隐私数据与微信接口盘点.md) 填写《小程序用户隐私保护指引》，只申报当前实际处理的信息和接口。
- 在“用户生成内容场景信息安全声明”中选择“包含”，UGC 场景勾选“用户资料”和“文本”，图片/视频/音频不勾选，内容安全机制勾选“使用平台建议的内容安全 API”。
- 配置合法域名（本项目当前核心闭环只使用微信云开发，通常不需额外业务域名）。
- 按 `docs/正式版测试清单.md` 完成开发者工具和真机验收。
- 上传体验版，邀请实际记账人员试用，再提交微信审核。
