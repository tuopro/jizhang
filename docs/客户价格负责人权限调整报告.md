# 客户价格负责人权限调整报告

日期：2026-09-21。状态：本地代码与回归完成；未部署 ledger、未上传体验版、未提交微信审核、未访问或修改正式业务数据。

## 1. 原权限位置与核查结果

- `cloudfunctions/ledger/index.js` 的 `ADMIN_MUTATIONS` 原包含 `saveCustomerPrice`；`services/member-security.js` 的 `assertMutationPermission` 在入口和事务内两次限制普通成员。
- `pages/client-ledger/client-ledger.wxml` 原以 `isAdmin` 显示“该客户价格表”。
- 共享 `services/ledger-repository.js` 的 `saveCustomerPrice` 原来没有独立角色/负责人校验；依靠云函数管理员门禁。新增和修改共用该 action，原来按客户与产品查找并更新。
- 原来没有独立价格读取 action；`bootstrap` 和写操作返回的企业快照包含 `customerPrices`，前端仓储同步读取。价格页直达没有客户权限校验。因此原读取并非严格的“只有 admin”，本轮补齐服务端过滤和专门读取校验。
- 当前没有独立的客户价格删除或停用 action。删除客户时清理价格的原规则保持不变。

## 3. 最终权限表达式

在真实 active membership、同一 tenant、真实 client 前提下：

```text
membership.role === 'admin'
OR (
  membership.role === 'member'
  AND (
    membership.id === client.ownerMemberId
    OR membership.id === currentOpenBillingPeriod.ownerMemberId
  )
)
```

本项目数据库成员主键是 `membership.id`；服务端向前端输出的 `identity.memberId` 来自该值。没有新增另一套 memberId 字段。

## 4. client owner 校验

服务端从真实 `OPENID` 取得 membership、active 状态和 tenantId。新建时重新读取目标 client；已有价格按真实价格的 `clientId` 读取 client，再比较真实成员主键与 `client.ownerMemberId`。不存在或不属于当前企业的客户直接拒绝。

## 5. current billing period owner 校验

价格读取/保存定向查询 `billing_periods`，条件为服务端 `tenantId + 真实 clientId + status='open'`，不从请求接收 period owner 或 periodId 作为授权来源，也不依赖企业快照前 1000 条是否包含目标记录。

只有唯一、已存储的开放期能够授予账期负责人价格权限；多个开放期属于异常，账期负责人分支拒绝授权，admin 和真实客户负责人分支仍正常。客户没有开放期时，admin 和客户负责人仍能管理价格。

## 6. 历史负责人为什么没有权限

`settled`、`closed`、其它客户/企业账期均不进入授权候选；不会扫描“曾经负责过的任意账期”，也不会采用 `allPeriods()` 为旧发货临时合成的兼容账期。结清后若成员不再是客户负责人或下一开放期负责人，就没有价格权限。

## 7. direct API 防伪造

- 新增受保护读取 action：`listCustomerPrices`、`getCustomerPrice`、`getCustomerPriceForProduct`；均经过真实 OPENID、active membership 和客户范围校验。
- `saveCustomerPrice` 支持新建、按客户/产品更新以及明确价格 ID 更新。已有价格先读真实记录、核验 `price.tenantId`，再以 `price.clientId` 授权；请求客户/产品与真实记录不一致时拒绝，不能重新绑定价格记录。
- `tenantId、role、memberId、ownerMemberId、periodOwnerMemberId、canManagePrices` 等前端字段不进入授权依据。
- 企业快照按真实成员过滤 `customerPrices`；包含 before/after 单价的独立价格审计同步过滤，数据库原审计不删除、不改写。
- 价格页不采用路由或缓存的 `canManagePrices`。先清空旧价格，再调用服务端读取；无权时提示并返回上一页，返回失败则到客户列表。成员身份失效沿用原身份失效页面。
- 快速记账的 `saveAsDefault` 原本也是客户价格写入路径，现在执行同一客户权限校验，防止绕过专属价格 action。无权客户的默认价不会下发；该成员仍可按原流程人工填写本笔成交价，但不能保存为该客户默认价。未改变金额、计价、单位、换算或缺价锁定规则。

## 8. owner 变化与并发

保存时在数据库事务内重新读取真实 membership、价格记录、客户和开放期。客户/账期负责人转移、账期结清、成员停用或删除后，旧页面再次保存会被拒绝；不使用打开页面时的许可。事务冲突重试会重跑读取与授权。

自动测试覆盖“请求进入事务前发生变化”和“读取后提交前发生冲突、重试时拒绝”两类情况。客户负责人转出后若仍为当前开放期负责人，可以继续使用账期负责人权限；新负责人即时获权。前端入口在页面刷新时重新计算，保存权限始终由服务端裁决。

## 9. 历史成交保护与审计

价格修改只写客户价格及原有价格审计，不更新已入账 shipment 或已结清 billing period。连旧发货缺失金额字段的兼容补齐也不会在价格保存时回写。

现有产品、数量、原单位、计价单位、换算、成交单价、金额快照继续作为历史账单、图片和 Excel 的数据来源。测试验证新发货可使用新价，旧发货逐字段不变；已结清账单与导出模型不变，最终 Excel 回读仍为原成交单价。

独立价格页原已有 `CREATE_CUSTOMER_PRICE` / `UPDATE_CUSTOMER_PRICE` 审计：新增保留 after，更新保留完整 before/after，时间和 `performedByMemberId`、姓名快照来自真实操作成员。普通负责人操作不会记为管理员。

另：快速记账的“保存为客户默认价”原没有独立价格 before/after 审计，只沿用发货审计。本轮保留该机制并增加权限校验，没有重建审计系统；该现状不等同于独立价格页审计缺失。

## 10. 其它权限与业务范围

标准产品、自定义产品新增/修改/停用、企业信息、成员、邀请、客户负责人转移、账期负责人调整、客户删除、其它发货修改、收款、结清权限均未扩大。发货修正页面内“保存客户默认价”的原管理员限制继续保留；本轮开放的是指定客户价格表管理，不顺带改写发货修正流程。

对比本轮基线确认 19 个保护文件逐字节一致，包括产品数据、价格计算、快速记账页面、隐私、内容安全以及图片/Excel 导出。18 个原仓储函数保持原样，包括 `updateShipment`、`postShipment`、`closeBillingPeriod`、负责人转移和产品管理函数。共享价格默认值 helper 仅加入价格授权与已有 tenantId 一致性检查。
