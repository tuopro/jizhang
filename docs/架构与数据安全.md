# 架构与数据安全

## 前端

- 原生微信小程序，普通 JavaScript。
- 页面只负责输入、展示和人工确认。
- `services/order-parser.js` 继续负责确定性规则识别。
- `services/ledger-repository.js` 是可测试的领域规则实现。
- `services/cloud-repository.js` 在正式运行时把写操作交给云函数，并刷新只读缓存。

## 云端身份与企业隔离

1. 小程序调用 `ledger` 云函数。
2. 云函数用 `cloud.getWXContext().OPENID` 取得真实微信身份。
3. 通过 `memberships` 查出 `tenantId`、角色和账号状态。
4. 前端传入的企业编号不参与权限判断。
5. 所有集合查询都加服务端解析出的 `tenantId`。
6. 普通成员可创建客户、记发货和登记收款；当前成员 ID 等于 `billing_period.ownerMemberId` 时还可确认结清本人负责且余额为 0 的账期。`admin` 可结清任意账期；修改账目、负责人调整、产品价格和成员管理仍只允许 `admin`。

正式版不存在公开注册或“空数据库首人自动建企业”通道。任何陌生微信用户都不会创建 enterprise 或 admin membership；必须持服务端签发的有效 `inviteToken` 加入已有企业。邀请记录位于 `member_invites`，默认 7 天有效；有效期内可供多个不同微信用户加入，管理员可以随时作废。

业务数据只通过受保护的 `bootstrap` 快照或受保护的云函数 action 进入前端。云函数会先用真实 `OPENID` 取得 `status=active` 的 membership，然后才查询企业快照。前端所有正式页面共用统一页面守卫；身份不存在或被停用时清除内存快照并跳转到未授权页。

发给前端的快照会递归删除 `openid` 和邀请 `token`，包括审计记录的嵌套前后快照。正式云函数日志只记录 action 和错误代码，不打印 `openid`、`inviteToken`、客户数据、金额或完整数据库对象。

企业内正常成员共享同一 `tenantId` 下的全部客户和账目。`ownerMemberId` 只用于负责人展示和筛选，不参与数据隔离。客户和账期保存负责人 ID 与姓名快照；发货、收款和审计保存实际操作人 ID 与姓名快照。

## 事务与审计

以下操作通过云数据库事务完成：

- 新增或修改客户。
- 新增或修改客户价。
- 新增、修改或停用自定义产品。
- 正式入账和客户价同步更新。
- 修正发货记录。
- 记录收款；余额归零后仍由管理员或当前账期负责人独立确认结清，并写入实际操作人的结清审计。
- 创建或作废多人邀请、成员加入、改名、停用/恢复和负责人转移。成员加入不会消耗邀请，也不会在邀请文档中累计使用者数组。
- 客户删除预览与执行：执行时在同一事务中重新校验角色、企业、客户和关联数据，避免使用过期预览。

防重复请求编号用于阻止重复发货和重复收款。正式入账、修正、价格修改、产品修改和收款都会写 `audit_logs`。

客户删除是物理删除，不增加停用、归档或恢复状态。普通成员只能删除没有发货、收款、账期和客户价格的空客户；管理员删除有账客户时必须准确输入客户名称。事务仅删除客户专属业务数据，保留共享产品、企业、成员、邀请、其它客户数据、旧审计和最终删除摘要。

## 历史保护

- 金额以整数分保存。
- 发货行保存产品标签和属性快照、原数量和单位、计价数量和单位、人工换算、成交单价和金额。
- 每笔发货独立保存 `itemsSubtotalCents`、`freightCents`和 `totalAmountCents`；服务端从成交行重新汇总商品金额，校验运费为非负整数分，再计算最终总额。
- 物流商、自提信息和物流单号仍保存在 `logistics`，不与 `freightCents` 混用。
- 已结清账期不可直接修改。
- 产品停用、改名或客户价格变化不会回写旧账。
- 修正后的账期货款不能低于已经收取的金额。

## 数据库权限

十个业务集合（含 `member_invites`）应在云开发控制台设置为“所有用户不可读写/仅云函数可访问”。参考规则见 [数据库权限规则.json](数据库权限规则.json)。前端代码不调用 `wx.cloud.database()`。

- 创建十个集合并关闭客户端直接读写。
- 完成管理员身份、企业名称、双微信成员协作和跨 `tenantId` 隔离测试。
- 配置自动备份并完成一次恢复演练。
- 完成隐私政策、用户数据处理说明和小程序备案/审核资料。
- 真机完成断网重试、重复点击和 20—30 条真实订单回归。
