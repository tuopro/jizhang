# 开发计划与完成状态

## 已完成

### 第一阶段：正式数据层、登录身份、企业隔离

- 默认启用微信云开发。
- `openid + memberships` 解析企业和管理员身份。
- 业务写入统一进入 `ledger` 云函数事务。
- 服务端从成员关系取得 `tenantId`，忽略前端企业编号。
- 本机领域仓储保留为自动测试和演示适配器，不作为生产数据源。

### 第二阶段：客户、产品和客户价格

- 客户搜索、新增、修改和欠款汇总。
- 标准规格只读，自定义规格可新增、编辑、停用。
- 客户专属价格按“客户 + 产品 + 单价 + 计价单位”保存。

### 第三阶段：快速记账接入客户账本

- 原规则识别模块原样复用。
- 正式入账写发货快照并更新客户本期账本。
- 物流信息与运费独立保存；商品合计、运费和含运费总金额由服务端统一计算。
- 已入账记录可修正，必须填写原因并保留前后审计快照。

### 第四阶段：收款和结清

- 全额、部分和多次收款。
- 收款金额不能超过剩余应收。
- 剩余应收为 0 时提示用户选择“暂不结清”或“确认结清本期”，不得自动结清。

### 第五阶段：对账单和历史

- 完成小程序内对账单预览。
- 用户确认结清后账期进入历史并只读保留；账期可跨月，月份只用于筛选。
- 新发货自动开启新账期。

### 第六阶段：首页、我的和统一 UI

- 四个底部入口：首页、客户、历史、我的。
- 白底、深蓝主色、橙色提醒、红色未收、绿色结清。
- “+ 记一笔”为首页主操作；识别测试页移到“我的”的开发测试入口。

### 第七阶段：单企业多人协作

- 服务端一次性邀请令牌，成员统一加入现有企业，不为新微信用户创建第二个企业。
- `admin/member` 两种角色；普通成员可创建客户、记发货和登记收款，高风险操作仅管理员。
- 客户负责人、账期负责人、发货/收款实际操作人和全量审计快照永久区分。
- 成员停用前检查并批量转移负责业务；最后一个管理员和当前登录管理员受保护。
- 客户与历史支持“全部 / 我负责的”，旧客户负责人只能由管理员明确批量补齐。

## 后续增量，不阻塞主体上线

1. 对账单微信分享长图。
2. PDF 和 Excel 导出。
3. 备份恢复自动化告警。

这些增量不得改变当前价格、规格、入账和历史快照规则。
