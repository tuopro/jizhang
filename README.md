# 客户往来记账微信小程序

这是面向 PVC 线槽等批发、工业品销售场景的独立微信小程序，产品定位只有三件事：

> 客户发货记账 + 按实际结清划分账期 + 对账 + 收款。

当前代码已从“识别测试版”升级为正式业务版。首页、客户、历史、我的四个底部入口已完成；现有规则识别、客户专属价、缺价锁定、单位确认和人工确认入账逻辑继续复用，没有改写成 AI。

## 已实现

- 微信 `openid` 登录、单企业多人协作、服务端 `tenantId` 隔离；任何没有有效 membership 的新微信用户都不会自动创建企业或管理员。
- 管理员生成7天有效的多人邀请卡片，可分享到同事群并随时作废；同事填写企业显示姓名后以普通成员身份加入同一账本，不依赖微信昵称。
- `admin/member` 两种角色、成员停用/恢复、最后管理员保护和离职前负责人批量转移。
- 客户负责人、账期负责人和每笔发货/收款实际操作人分别记录；姓名快照保护历史。
- 客户新增、修改、搜索和当前欠款查询。
- 客户删除：普通成员只可删除无任何正式业务关联的空客户；管理员可经名称强确认彻底删除客户专属账务，并保留删除摘要审计。
- 标准产品查看；自定义产品新增、编辑、停用。
- 客户专属价格新增、修改和产品搜索；不存在通用价格。
- 快速记账：粘贴文字、规则整理、人工选产品、缺价补录、单位换算确认、二次确认、正式入账。
- 运费独立记账：物流信息与运费分开，商品合计、运费和含运费总额均按整数分保存。
- 客户账本：本期货款、已收、剩余应收、发货次数、发货和收款记录。
- 错误账目修正；保留修改前后快照、原因和审计记录。
- 全额、部分和多次收款；部分付款不会结束账期，剩余为 0 时也不会静默结清。
- 只有管理员或当前 `billing_period.ownerMemberId` 对应的账期负责人确认“结清本期”，才生成只读历史账单；结清后的下一笔发货自动开启客户下一期。
- 账期允许跨月，月份仅用于历史筛选，不参与账期 ID 或边界判断。
- 对账单小程序内预览，包含发货、商品、数量、成交价、小计、总货款、已收和剩余应收。
- 首页最近记账、最近收款、未结客户和总应收。
- 客户与历史支持“全部 / 我负责的”；管理员可查看操作记录并明确补齐旧客户负责人。

暂未实现长图、PDF 和 Excel 导出；它们不阻塞当前记账闭环。

## 数据与安全结构

正式版默认 `dataAccessMode: 'cloud'`。前端通过 `cloudfunctions/ledger` 访问云数据库，不能直接指定或信任 `tenantId`。云函数根据微信 `openid` 查询 `memberships`，取得企业和角色后才执行事务。

核心集合：

- `enterprises`
- `memberships`
- `member_invites`
- `clients`
- `products`
- `customer_prices`
- `shipments`
- `payments`
- `billing_periods`
- `audit_logs`

金额按整数分保存；发货记录保存成交时的产品、数量、单位、单价、换算和金额快照，并独立保存 `itemsSubtotalCents`、`freightCents`和 `totalAmountCents`。服务端会重新计算“商品合计 + 运费 = 本次合计”，不信任前端总额。`billing_periods` 为每位客户维护连续 `sequenceNo`；新账期 ID 不再由月份生成。旧 `periodKey/sequence/settledAt` 数据继续兼容读取，不在查询时静默改写。修改产品或客户价格不会改变历史账单。

客户删除不使用软删除。云函数在事务内重新统计并删除目标客户的 `clients、shipments、payments、billing_periods、customer_prices` 数据；`products、memberships、enterprises、member_invites`、其它客户数据和 `audit_logs` 不进入删除范围。

## 开发与检查

```bash
npm test
npm run check
```

当前自动检查包括：核心规则、正式账期闭环、企业隔离、成员邀请和权限边界、负责人/操作人快照、重复提交、收款边界、账目修正审计、JavaScript 语法、微信 WXML/WXSS 原生编译，以及前端和云函数共享业务规则一致性。

## 仍然坚持的业务边界

- 不使用 AI、DeepSeek 或不可审计的语义猜测。
- 不猜价格、不设置市场通用价、不静默创建产品。
- 规格和齿型以 `data/product-specs.js` 为权威。
- 米、根、箱不一致时必须人工确认换算或改价。
- 正式入账、修正、收款和结清均二次确认并写审计。
- 已结清账期默认只读；历史成交快照永久保留。
- 当前不做库存、采购、利润表、生产管理、CRM 或复杂 ERP。
